# Article writing

Use this reference when the user wants an article, essay, post, or transcript shaped into a piece of writing.

## Choose the stage

- **Fragments:** the user has an idea or scattered material and wants to explore without committing to a thesis or outline.
- **Shape:** the user has a pile of material and wants to build the article paragraph by paragraph.
- **Beats:** the user wants a guided sequence of small moves, choosing the next beat as the piece develops.

If the user only wants advice or a draft in chat, keep the work in chat. If they want a persistent draft and give no path, ask once where it should live. Never create or overwrite a file just because the task is called writing.

## Fragments

Interview the user for material without imposing an outline. Capture sharp sentences, claims with reasons, scenes, examples, quotes, complaints, half-thoughts, and useful leading words. Preserve the order in which fragments arrive. If a file is the agreed workspace, read it before every append and add only new material; the user's edits win.

Move to an exploit stage when the user has enough material and is ready to choose a direction.

## Shape

Read the source material end to end. Establish what the reader already knows, then draft two or three genuinely different openings. Show them before writing the article and let the chosen opening set the obligation for what follows.

Grow one paragraph at a time. After each paragraph, ask what the reader needs next, pull only material that answers that need, and choose the form that fits the move. Prose carries connected reasoning; lists carry parallel items; tables carry repeated fields; quotes carry wording that matters. Name gaps instead of inventing examples, evidence, or experiences.

## Beats

Establish prerequisites, offer two or three reachable starting beats, write only the chosen beat, then reread the article before offering the next candidates. Track which concepts the reader has already met. A beat may be one sentence or several paragraphs, but split it when it contains more than one move. End the journey when the argument is complete; unused source material can remain unused.

## Completion check

Before delivery, confirm that the opening, argument order, evidence boundary, and voice still match the source. Run the core prose self-audit. If the piece is technical documentation, also read `technical-docs.md` for its document mode and style layer.
